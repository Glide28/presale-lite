2. **0:30–1:15 Архитектура.** Слайд со схемой: UI → API → сервис → LLM/pricing/storage. Почему монолит и SQLite.
3. **1:15–1:45 Ключевые решения.** Деньги считает код; ответ модели валидируется; провайдер LLM заменяем.
4. **1:45–3:15 Демо.** Создать пресейл из docs/sample_tz.txt → вопросы → расчёт → бюджет/риски → чат.
5. **3:15–3:45 Качество.** Тесты, CI, логирование, Docker Compose.
6. **3:45–4:00 Итоги и развитие.**

Слайды: 5–6 (проблема, сценарий, архитектура, решения, демо-скриншоты, итоги).

## Вероятные вопросы
- **Чем отличается от решения команды?** Другая архитектура и стек (монолит, SQLite, Streamlit), отдельный
  тестируемый модуль расчёта бюджета, mock-режим для воспроизводимости.
- **Почему не доверять модели бюджет?** Арифметика должна быть проверяемой; модель оценивает только часы по ролям.
- **Что если модель вернёт мусор?** Парсинг с извлечением JSON, нормализация, отбрасывание неизвестных ролей/часов, ошибка 502.
- **Как с безопасностью данных?** Токен-доступ, ограничения на файлы, возможность on-premise и локальной LLM через `LLM_BASE_URL`.
- **Как масштабировать?** SQLite → PostgreSQL через слой storage, вынос LLM-вызовов в очередь.
- **Что в проекте не доработано?** Роли, многопользовательность, точность оценки зависит от модели.
